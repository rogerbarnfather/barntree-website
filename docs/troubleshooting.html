A Template is broken #

The check says which, and why:

$ vendor/bin/barntree check
Barn: …/allotment
Checking the trees in …/allotment/.barn/barntree/trees
Allotment: valid
Pond: broken: Type 'Pond' is of 'Fish', which is not one of the tree's types.

Open the file and fix what it names, or restore it from version control. A file that doesn’t name a Template, or names one another file already holds, stops the check before any Template is read, as fault: <file>: <reason>. One bad file refuses its whole folder, because a Template left out without a word would be worse.

A file I changed by hand doesn’t match its history #

A file edited outside Barntree can differ from its last recorded revision, and a read says so. Open it in the app, or save it through a command, and the save records what was there first.

Known limits #

  • A document that breaks a rule reports one rule at a time. Only a document that doesn’t fit the shape reports every fault at once.
  • Members’ names are matched exactly as typed, so Kitchen and kitchen can sit in one list.
  • The store reads its folder once, when it is first asked. A file added after that is not seen until a new store is made.
  • A Construction can’t be exported, restored to an earlier revision, or moved to a newer Template yet.
  • Tags are written in the file and not edited in the app or on the command line.
